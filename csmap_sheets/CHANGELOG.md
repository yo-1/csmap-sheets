# v0.9.0 — WebP非可逆(lossy)出力の追加

- 背景：ユーザーから「WebPだが非可逆を求められた」との要望（2026-09-28）。v0.8.0では
  WebPは可逆(lossless)のみ実装していたが、配信先クライアントの要件により非可逆(lossy)が
  必要になったため、以前議論・確認済みの仕様（GDAL WEBPドライバのQUALITY・LOSSLESSオプション、
  gdal.org WEBPドライバページで確認）どおりに選択式で追加した。
- 「XYZ画像形式」でWebPを選んだ場合、新設の「WebPを可逆(lossless)にする」（既定True＝従来どおり
  可逆）を無効にすると非可逆になり、「WebP非可逆時のQUALITY」（1-100、既定75、GDAL WEBPドライバの
  既定値と同じ）で圧縮率を指定できる。両パラメータともAdvanced（詳細パラメータ）扱い。
- 実装は`_tile_encoder()`の作成オプションを条件分岐：可逆時は`LOSSLESS=TRUE`（従来どおり）、
  非可逆時は`LOSSLESS=FALSE`＋`QUALITY=<値>`を明示的に指定（GDALの暗黙のデフォルトに頼らない）。
- WEBPドライバが利用できない環境では、可逆・非可逆いずれの設定でも**従来どおりPNGへ黙って
  切替えず**、明確なエラーで停止する（PNG/WebP・LEMいずれの経路とも同じ「フェイルファスト」方針）。
- `run.json`/`xyz.json`のエンコーダー記録（`encoder`）に`quality`フィールドを追加
  （可逆時は`null`、非可逆時は指定値）。
- 回帰テスト追加：非可逆選択時の作成オプション（`LOSSLESS=FALSE`・`QUALITY=<値>`）の単体テスト、
  `xyz_webp_lossless`/`xyz_webp_quality`の不正値の拒否、非可逆WebP出力の統合テスト（単色領域の
  復元誤差が許容範囲内であることを確認。可逆時と異なり画素完全一致は求めない。GDAL実機が必要な
  ためこの開発環境ではスキップ、Windows/QGIS実機での実行が必要）。
- **実機検証済み（2026-09-29追記）**：Windows/QGIS 3.44・公開データ（甲府エリアで検証、標高
  ラスタ入力、セルサイズ1m・0.5mの2条件）で実行し、QGIS同梱GDALにWEBPドライバが実在すること、
  可逆(lossless)WebP出力が657枚のタイルを正常完了することを確認した（VALIDATION.txt参照）。
  非可逆(lossy)WebP出力と、森林航空レーザ成果(LEM)大量ファイルでの実機確認は2026-09-30以降に
  別途実施予定で、引き続き未確認。

# v0.8.1 — 森林航空レーザ（LEM）入力の応答なし不具合修正

- 背景：ユーザー報告（2026-09-28「Lemが流れない」）。森林航空レーザ成果（LEM・CSV格子・TIFF・
  GeoTIFF・ZIP）を入力形式として、794件の`.lem`ファイル（同名の`.csv`メタデータを1件も伴わない
  データセット）を選択して実行すると、QGISのウィンドウタイトルに「(応答なし)」が表示されたまま
  長時間戻らず、ログタブへの切替えもできなくなる（＝UIメインスレッドがブロックされている状態）。
- 原因：`engine/forest_dem.py`の`expand_sources()`で、`.lem`ファイルに対応する同名`.csv`が
  直接存在しない場合、`path.parent.glob('*')`でフォルダ内の全ファイルを毎回再走査してから
  ステム名一致を探していた。対応CSVを持たないLEMファイルがN件あると、この再走査がN回発生し、
  1回あたりの走査コストもフォルダ内ファイル数に比例するため、全体としてO(N²)のファイルシステム
  走査になる（本件N=794では概算約63万回のファイルエントリ比較に相当）。この処理は
  `algorithm.py`の`prepareAlgorithm()`（`validate_config()`→`discover()`経由）から呼ばれており、
  QGIS Processingではこの`prepareAlgorithm()`がUI/メインスレッド上で実行されるため、走査が
  終わるまでQGIS全体の描画・入力処理が止まっていた。
- 修正：`expand_sources()`にディレクトリ単位の`.csv`一覧キャッシュ（`csv_index_cache`）を追加し、
  同一フォルダに対する全件列挙を1回だけ行うように変更（O(N²)→O(N)＋ディレクトリ数分の列挙）。
  拡張子の大文字小文字を区別しない挙動（修正前の`p.suffix.lower()=='.csv'`判定）は維持している。
- **これは性能の不具合修正であり、データ要件そのものは変更していない**：`.lem`ファイルには
  依然として同名の`.csv`メタデータが必須であり、見つからない場合は`classify_sources()`が
  従来どおり`ValueError('LEM requires its companion metadata CSV with the same stem: ...')`で
  即座に停止する（PNG/WebPの方針と同様、要件を満たさない場合に黙ってスキップ・代替しない）。
  本件の794件のデータセットに`.csv`が実在しない場合、この修正だけでは処理は成功せず、
  数十秒程度で明確なエラーメッセージが出るようになる、という違いになる。`.csv`メタデータの
  所在確認・入手はユーザー側の対応が必要。
- 回帰テスト追加（`tests/test_inputs.py`）：対応CSVを持たないLEMファイル50件に対して、
  同一ディレクトリの列挙が1回だけであることをカウント検証するテスト、および大文字小文字が
  異なる`.csv`（例：`A.CSV`）でもキャッシュ経由で対応付けできることを検証するテスト。
  GDAL/QGIS実機は不要でこの開発環境でも実行可能。全80件（うち実機依存8件スキップ）で
  リグレッションなしを確認済み。

# v0.7.0 — 標高色の下限/上限の自動検出

- 「標高色の下限/上限を自動検出する」オプションを追加。有効にすると、DEMを再投影・モザイク化した
  直後に実際の標高min/max（GDAL近似統計）を検出し、余白（既定50m、変更可）を加えた範囲を自動的に
  正規化範囲として使用する。ELEV_MIN/ELEV_MAX欄は無視される。
  FMEマニュアル別紙3の「標高200〜2,000m」は長野県のLEMデータによる実績値であり、対象地域によっては
  実際の標高分布と合わないため（山梨県等、低標高域を含む場合に谷底が下限へ張り付いて階調を失う事例あり）追加。
- 検出結果は`run.json`の`elevation_range_detected`（検出した生の範囲）・
  `rendering.normalization.elevation_m`（実際に使用した余白込みの範囲）に記録され、後から確認できる。
- 組込み設定プロファイル（標準CS・1m等）を選択した場合は、プロファイル側の固定範囲が優先され、
  自動検出は無効になる（再現性を優先）。
- テスト1件追加（GDAL環境でのみ実行、合成DEMのmin/maxを検出できることを確認）。

# v0.6.0（プラグイン・計算エンジン0.6.0）— Claude/ChatGPT両実装の突き合わせ統合

Claude（本ツール）とChatGPTがそれぞれ独立に作成したv0.5.2相当の実装を比較し、双方の長所を統合した。

**方針決定（2026-09-24）**：本家QGISプラグイン[waigania13/CSMapMaker](https://github.com/waigania13/CSMapMaker)
（SAGA曲率＋ColorBrewer段階配色をQGISキャンバス上で半透明合成する方式）のソースを確認した結果、
FMEマニュアル（Pacific Spatial Solutions社、固定RGBシード値の5レイヤー加重合成）とは
曲率の定義・平滑化条件・配色方式のいずれも異なる別実装であることが判明した。本プラグインは
**FMEマニュアルへの準拠を継続する**方針とし、waigania13版アルゴリズムへの作り直しは行わない
（利用先の作業がFMEワークスペース一式を用いる前提であるため）。詳細はREADME_ja.mdの
「『本家』との関係についての方針」を参照。

- **バグ修正**：`validate_config`の裸のデフォルト値が、`render_mode`未指定（＝`independent_v040`扱い）
  でも`curvature_limit=0.03`（FME方式の値）のままだった。QGIS画面からの利用では組込みプリセットが
  常に`.05`を強制上書きするため症状が出ないが、`curvature_limit`を省略した外部JSONプロファイルや
  裸のconfigでは、独自方式のはずが誤って曲率±0.03相当の見た目になっていた。バグ再現テストと
  修正（裸のデフォルトを0.05へ）を追加。`fme_manual`側の暫定値0.1（未指定時のみ適用）は変更なし。
- **組込みプロファイルに「林野庁近似設定（暫定）」を追加**：従来「標準CS・1m」「試験処理・2m」は
  いずれもFMEマニュアル値(±0.1)のみで、林野庁の設定に近いとされる暫定値(±0.03)は数値欄手入力か
  外部JSON経由でしか選べなかった。ワンクリックで選べる「林野庁近似設定（暫定）・1m（曲率±0.03）」を追加。
- **FME方式のRGBストレッチ既定値を「なし」から「長野県実績値」へ変更**：「FMEマニュアル方式」を
  選んだだけの初期状態でマニュアル記載の色の鮮明化が再現されるようにした（従来は既定が「なし」で、
  ストレッチ欄を別途変更しない限りマニュアルどおりの発色にならなかった）。
- テスト2件追加（`ConfigDefaultsTests`）、`test_qgis.py`にPROFILE選択肢・FME_STRETCH既定値の検証を追加。
- **曲率換算の直接確認**：`s2_DEMラスターからCS立体図への変換.fmw`を実際に読み、曲率計算の
  `RasterConvolver`が`KERNEL_WEIGHTS="0 -1 0 -1 4 -1 0 -1 0"`（本プラグインと同符号の5点ラプラシアン）・
  `KERNEL_DIVISOR="$(CELL_SIZE)**2 * 0.01"`であることを確認した。これによりFMEマニュアルの
  「曲率±10」が本プラグインの「±0.1 1/m」に対応することが裏付けられたため（既存の
  VALIDATION.txt記載を独自に再検証）、UI・コード中の「暫定」表記を整理した。
- **新たに判明した差異（未対応）**：同FMWの`RasterSlopeCalculator`は`ALGORITHM="Horn"`を
  使用しており、本プラグインの中央差分（`np.roll`によるdz/dx, dz/dy）とは計算方法が異なる。
  傾斜由来のレイヤー（傾斜A・B）はFMEと画素完全一致しない要因として残る。本パッチでは対応せず、
  次の課題として記録する。
