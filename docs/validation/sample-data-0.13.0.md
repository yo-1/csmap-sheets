# Windows受入用の人工DEMサンプル（0.13.0）

人工的に作った地形です。実在地域の測量成果ではなく、測量精度やFME完全互換の証明には使えません。
データはCC0-1.0。GeoTIFFを作るためのPythonやGDALは受入側では不要です。
プラグインZIPとは別配布で、申請用ZIPを変更しません。

## 内容

- `dem_full.tif`：400×400画素、1m格子、EPSG:6677（JGD2011平面直角IX）。
- `tiles/dem_west.tif`・`dem_east.tif`：同じDEMを東西に分割した200×400画素。
- 山・窪地・波状の地形、内部のNoData穴、左下の欠測端部を含みます。
- NoData=-9999。標高は人工的なm値、実在の鉛直基準はありません。
- 全体と分割2枚は、NoDataを含め同じ値です。

## 最初のテスト（全体DEM）

サンプルZIPをローカルの短いパス（例 `C:\GIS_test\sample`）へ展開します。
QGISに `dem_full.tif` を読み込むと、山・谷と透明な穴が表示されます。
CS Map Sheetsの処理画面では次を指定します。

|項目|指定|
|---|---|
|設定プロファイル|画面の設定を使用|
|入力形式|標高ラスタ|
|入力ファイル|dem_full.tifだけを選択|
|入力フォルダー|空欄|
|水平座標系|GeoTIFFから自動。出力はEPSG:6677|
|単位・鉛直基準の確認|人工DEMのm値であることを確認してチェック|
|図郭レベル|500|
|出力セルサイズ|1m|
|曲率平滑化|地上距離3m|
|傾斜|Horn法|
|描画|FMEマニュアル方式、他の配色は既定|
|欠測・端部|標準（safe_mask）|
|マージ済み標高DEM保存|オン|
|XYZ|最初はオフ|
|出力先|空の作業用フォルダー（例 `C:\GIS_test\out_full`）|

実行後、CS画像・図郭索引と単独のdem_merged.tifを再読込します。
期待結果：山・谷が着色され、内部の穴とその周辺が透明、欠測値が極端な地形として着色されない。
図郭索引は枠線のみです。出力は毎回別のcsmap日時フォルダーに入ります。

## 追加テスト

1. **分割入力**：入力ファイルを空にして入力フォルダーを `tiles` に変更し、別出力先へ実行。
   全体DEMと地形の位置・色が一致し、東西の接合部に余計な線・隙間がないことを確認。
   サンプル親フォルダー全体を入力にしないでください（全体DEMとの重複になります）。
2. **欠測方式**：同じDEMをPSS近似方式で別出力へ実行。穴中心は透明のまま、穴周辺・端部の表示が標準方式と変わることを確認。
   正解画像との完全一致を要求するテストではありません。
3. **設定保存**：拡張子なしのJSON保存先を指定して実行。`.json`が付き、v5形式で保存されることを確認。
   読込JSONとして再利用し、run.jsonの欠測方式・DEM保存設定が保持されることを確認。
4. **旧設定**：お持ちの旧JSONがあれば別出力で読込み、方式の扱い・警告を確認。
   旧JSONのない場合、この項目は未実施として記録します。
5. **Web出力**：XYZをオン、最小14・最大16でPNGを生成。次にWebPを別出力へ生成。
   WEBPドライバーなしでは明確なエラーになれば期待どおりです。

失敗・未実施・ログ保存先＿＿

これは合成データの機能確認です。最後に普段使う実DEMでも小範囲を1回実行してください。

## 作成側で確認したこと

Linux/QGIS 3.44の環境でGeoTIFFの配列・格子・NoDataの書込み後再読込に成功。
0.13.0エンジンで全体1枚・分割2枚を実行し、結合CS画像のRGBA全画素一致を確認。
PSS近似方式も実行成功、標準方式との出力差を確認。
この結果はWindows上の受入完了を意味しません。
