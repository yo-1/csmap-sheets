# Issue #45 フォーム入力項目の整理案（2026-10-31）

対象の声：「フォームの入力項目が、どこまでがGeoTIFFなのか、LASなのかが
分かりづらいので、タブでグループ分けするなどしたほうが良いと思います。」

パラメータ名・型・既定値は変えない（モデル・バッチ・プロファイル互換の維持）。
本書は整理案と推奨であり、実装の判断は別途。

## 1. 現状の実測（main v0.13.1）

- 項目は【設定】【入力】【点群】【テキスト】【森林レーザ】【出力・図郭】
  【地形計算】【配色】【XYZ】【出力】の区分ラベル付きで、追加順も区分ごとに
  そろっている（静的抽出で確認。ループ生成の色・ストレッチ項目を含む
  監査時の総数は92項目）。
- つまり「並びの乱れ」ではなく、**選んでいない形式の項目まで常時すべて
  表示される**ことが分かりづらさの本体。入力ガイドにも「画面上には
  全形式の項目が表示されます」と明記されている。
- 個別の混乱点：
  - DEMS（標高ラスタ欄）が共通の【入力】区分の中にあり、別形式を選んでも
    目立つ位置にある（Issue #71 の誤解の発生源。案内文とヘルプで対処済み）。
  - 似た名前の項目が形式ごとに並ぶ（CELL／TEXT_CELL／FOREST_CELL、
    NODATA／FOREST_NODATA など）。
  - 点群の詳細項目（SMRF 系・POINT 系）は、点群を使わない利用者にも常時見える。

## 2. 制約

- QGIS Processing の標準ダイアログにタブはない。タブ化は標準ダイアログの
  置き換え（カスタムUI）を意味し、モデルデザイナー・バッチ処理・
  ヘルプ連携との整合と保守を新たに抱える。
- 区分ラベルは PARAMETER_SECTIONS のキーから自動付加されるため、
  区分名の変更は全項目のラベルへ一括で効く（＝低コストで効く変更点）。

## 3. 選択肢

### 案A：ラベルと説明の整理（工数小・リスク小）
- 区分名へ対象形式を併記する：【点群】→【点群（LAS・LAZ）】、
  【テキスト】→【テキスト（XYZ・CSV・TXT）】、
  【森林レーザ】→【森林レーザ（LEM・CSV格子・TIFF）】など。
- DEMS のラベル・説明に「標高ラスタ形式のみ」を含める（#71 のヘルプ明記と同方向）。
- ヘルプ冒頭に「形式 × 使う区分」の対応表を1つ置く。

### 案B：形式固有の詳細項目を「高度なパラメータ」へ分離（工数中）
- SMRF 系・POINT 系の詳細値、FME 色の個別指定など、通常は既定値で足りる
  項目に Advanced フラグを付け、初期表示を絞る。
- ただし Advanced は形式連動ではない（展開すると全形式分が見える）ため、
  効果は「初期表示の削減」まで。項目が見つけにくくなる副作用と、
  手順書の画面説明とのずれ（再撮影が要る）がある。

### 案C：タブ式カスタムダイアログ（工数大）
- 字面どおりのタブ分けは可能だが、標準ダイアログの置き換えになる。
  互換・保守・実機検証の負担が大きく、現時点では見送りを推奨する。
  将来やるなら「専用ダイアログ＋裏側は Processing」の大規模改修として
  独立に判断する。

## 4. 推奨手順

1. 次版で案Aを実施する（#71 の案内改善と同じ系統で、低リスク）。
2. 案Bは案Aの反応を見て、点群の詳細項目から段階的に。
3. 案Cは見送り。

## 5. ほかの作業との順序

- ラベルを変えると手順書の画面説明・撮影がずれるため、実機セッションの
  画面撮影（PR #75 §5、PR #77 の最小項目）は、案Aの採否が決まってから
  行うのが手戻りがない。
